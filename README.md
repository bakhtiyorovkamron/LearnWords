# LearnWords

## Мониторинг

Сервер мониторится [Beszel](https://beszel.dev): хаб (веб-панель) и агент работают на этом же сервере
(сервисы `beszel` и `beszel-agent` в `docker-compose.yml`, версия закреплена). Панель не опубликована
в интернете — хаб слушает только `127.0.0.1:8090` на сервере, вход только через SSH-туннель.

### Вход в панель

```sh
ssh -L 8090:localhost:8090 user@IP_СЕРВЕРА
```
Пока SSH-сессия открыта, откройте в браузере http://localhost:8090.

### Первый запуск

1. На сервере: `docker compose up -d beszel`.
2. Откройте панель через туннель и создайте администратора Beszel.
3. **Агент.** В панели нажмите «Add system»:
   - Name — любое (например, `yodla`), **Host / IP** — `/beszel_socket/beszel.sock`;
   - скопируйте из окна **KEY** и **TOKEN** в `.env` на сервере:
     ```sh
     BESZEL_KEY='ssh-ed25519 AAAA...'
     BESZEL_TOKEN=...
     ```
   - `docker compose up -d beszel-agent`, затем «Add system» в панели. Через минуту появятся метрики.

   Пока `BESZEL_KEY` не задан, агент не может стартовать и перезапускается — это нормально до шага 3.

### Порт 8090 закрыт снаружи

Проверка с **другого** компьютера (без туннеля):
```sh
curl -m 5 http://IP_СЕРВЕРА:8090   # должно быть: Connection refused / timeout
```
На сервере: `ss -ltnp | grep 8090` — адрес должен быть `127.0.0.1:8090`, не `0.0.0.0:8090`.

### Уведомления в Telegram

Настраиваются в панели: Settings → Notifications, по инструкции
https://beszel.dev/guide/notifications/telegram (бот через @BotFather, URL вида `telegram://<token>@telegram?chats=<chat_id>`),
затем кнопка «Test».

### Алерты

На карточке системы — значок колокольчика (Alerts). Включите:

| Алерт | Порог |
|---|---|
| Status (система не отвечает) | вкл. |
| CPU Usage | > 80 %, длительность 10 минут |
| Memory Usage | > 85 % |
| Disk Usage | > 80 % |

## Telegram-бот (привязка аккаунта)

Пользователь нажимает «Подключить» в профиле → сайт открывает `https://t.me/<бот>?start=YL-XXXXXX`
(одноразовый код, 10 минут) → в боте «Start» → бот привязывает Telegram к аккаунту.

За первое подключение — подарок: `TelegramBonusCredits` (сейчас 2) фото для импорта, в той же
транзакции, что и привязка. Один раз на Telegram-аккаунт и один раз на пользователя (таблица
`telegram_bonuses`, без внешних ключей — запись переживает удалённый аккаунт), в `credit_ledger`
с причиной `telegram`. Пока Telegram не подключён, сайт показывает окно «Подключите Telegram» при
каждом открытии (без сохранения в storage); «Позже» скрывает его до перезагрузки.

Переменные в `.env` на сервере:

```sh
TELEGRAM_BOT_TOKEN=...            # от @BotFather; никогда не попадает в логи и ответы API
TELEGRAM_BOT_USERNAME=yodla_bot   # без @
TELEGRAM_WEBHOOK_SECRET=...       # случайная строка: только A-Z a-z 0-9 _ -, до 256 символов
TELEGRAM_WEBHOOK_URL=https://yodla.fun/api/telegram/webhook   # это значение по умолчанию в docker-compose
```

Секрет можно сгенерировать так: `openssl rand -hex 32`.

Публичный адрес вебхука — `https://yodla.fun/api/telegram/webhook` (Caddy проксирует `/api` в бэкенд).
При старте бэкенд сам вызывает `setWebhook` с этим адресом и секретом; ошибка только пишется в лог.
Telegram присылает секрет в заголовке `X-Telegram-Bot-Api-Secret-Token`; без совпадения вебхук отвечает 401.
Без `TELEGRAM_BOT_TOKEN` (или `TELEGRAM_BOT_USERNAME`) привязка выключена: эндпоинты отвечают 503 `telegram_unavailable`.

Проверка: `curl -s "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/getWebhookInfo"` — `url` и `last_error_message`.

## Чат по заявке на покупку

У каждой заявки (`purchase_requests`) есть чат покупателя с админами: текст до 1000 символов и/или
фото (JPEG/PNG/WebP/GIF до 5 МБ). Покупатель: `GET/POST /api/me/purchases/:id/messages`
(`?after=<id>` — до 50 сообщений после этого id), админы: `/api/admin/purchases/:id/messages`.
Покупатель — не больше 20 сообщений за 10 минут. В отменённую или отклонённую заявку писать нельзя
(409 `chat_closed`), история остаётся. Подтверждение и отмена оставляют в чате системную строку.

- Фото хранятся в Postgres (`purchase_message_images`), в сообщении — только ключ; отдаются по
  `.../messages/:mid/image` только участникам.
- Текст, похожий на номер карты (13–19 цифр подряд, можно через пробел или дефис, или 4 группы
  по 4 цифры), сохраняется скрытым: другая сторона его не видит, автор видит предупреждение, админы —
  с пометкой и кнопкой «Показать». Тексты сообщений не пишутся в логи.
- Новое сообщение админа: покупателю уходит уведомление без текста — в Telegram, если он подключён,
  иначе push. Значок непрочитанного у админа — сообщения покупателя после последнего прочтения админом.
