# LearnWords («Yodla»): описание проекта

Продукт живёт на **yodla.fun**.

## 1. Что это

LearnWords — веб-приложение (PWA) для изучения иностранных слов. Слова берутся из реального контекста: из предложения, которое пользователь вводит или фотографирует, а не из готового списка. ИИ превращает контекст в карточки: перевод, транскрипция, пример с пропуском, грамматика. Дальше слова запоминаются по системе интервальных повторений.

Изучаемые языки: немецкий (по умолчанию), английский, французский, корейский. Язык интерфейса и переводов: русский, английский, узбекский. Изучаемый язык выбирается при регистрации и закреплён за аккаунтом.

## 2. Как это работает для пользователя

**Добавление слов**
- **Контекст.** Пользователь вставляет текст, из которого берутся слова.
- **Поиск слова.** ИИ даёт перевод, транскрипцию и пример с пропуском `___`. Для пропуска хранится точная форма слова (`example_gap_answer`), например «schmeckt» или «den Tisch».
- **Импорт по фото.** Фото или скриншот страницы разбирается ИИ на слова. Браузер заранее проверяет качество (слишком маленькое, тёмное или размытое) и не тратит квоту на заведомо плохие снимки. Обрезки в одну-две строки тоже проходят.
- **Проверка слова при вводе.** ИИ исправляет опечатку, приводит слово к начальной форме и подсказывает артикль. Варианты: `ok`, `corrected`, `unknown`, `error`. Пользователь принимает или отклоняет правки (`word-fixes`).
- **Стартовая папка «Introductions»** с 15 бытовыми фразами достаётся каждому новому пользователю.

**Организация**
- **Папки.** Папку можно переименовать и перекрасить, слова можно переносить и удалять пачкой.
- **Общий доступ.** Папку можно расшарить по публичной ссылке `/s/:token`. Предпросмотр открыт без входа, а импорт в свой аккаунт требует входа. Ссылку можно перегенерировать или отключить. Чужую папку на другом изучаемом языке и свою собственную импортировать нельзя.

**Обучение**
- **Повторения по коробкам (Лейтнер).** Пять уровней с интервалами 1, 2, 4, 7 и 14 дней. Размер сессии: 10, 20, 50 или все слова.
- **Практика.** Дополнительная тренировка по всей коллекции, когда повторять нечего. Режимы: сложные, случайные, недавние. Практика не меняет прогресс слов, а идёт только в статистику и серию.
- **Колода карточек.** Свайп на пружине и переворот карточек.
- **Тесты и озвучка** (`quiz`, `speech`).
- **Ежедневная цель.** Кольцо прогресса, недельная полоса, серия дней.
- **Статистика.** График повторений и количество выученных слов.

**Истории**
- ИИ пишет ежедневную историю на выученных словах, с переводом на язык интерфейса. Её можно вычитать (proofread).
- Пользователь может создать собственную историю, отредактировать её или удалить.

**Герой.** Персонаж-талисман с шестью стадиями роста: от 0, 50, 200, 500, 1300 и 2400 выученных слов. У него есть настроение: idle, sleepy (слова ждут, а тренировки сегодня не было), happy (всё повторено) и sad (серия оборвалась вчера). Он говорит фразы на изучаемом языке из выученных слов. Показ героя включается и выключается флагом `FEATURE_HERO_ENABLED`.

**Прочее**
- Темы оформления.
- Установка как PWA, с оффлайн-страницей и service worker.
- Web Push напоминания (VAPID), включаются подпиской.
- Форма обратной связи.
- Баннер для встроенных браузеров (in-app).

## 3. Администрирование

Админ-панель `/admin` доступна только пользователям с ролью `admin`, роль проверяется в БД при каждом запросе. В ней можно:
- смотреть пользователей и общую статистику;
- банить и удалять пользователей;
- читать обратную связь;
- отправлять push-уведомления;
- подтверждать и отклонять заявки на покупку фото, вручную менять баланс купленных фото;
- запускать фоновую проверку слов (`word-check`) по всей базе.

**Фичефлаги и квоты.** Для каждого пользователя админ включает и выключает функции: `photo_import` (по умолчанию 5), `daily_story`, `word_search`, `story_autotranslate`, `theme_picker`. У функций бывают лимиты, а часть из них может быть выключена по умолчанию, пока не включит админ.

### Покупка фото (ручная оплата)

Бесплатный лимит `photo_import` (5 фото в день) остаётся. Когда он кончился, тратятся купленные фото: отдельный баланс, который не сгорает. Сначала всегда уходят бесплатные фото дня, потом купленные. Если не хватает обоих, сервер отвечает `429 daily_limit` с полями `limit` и `credits`. Если ИИ не справился, фото возвращается туда, откуда было взято.

| Пакет | Фото | Цена |
|---|---|---|
| `photo_35` | 35 | 25 000 сум |
| `photo_100` | 100 | 59 000 сум |

1. Пользователь выбирает пакет, и создаётся заявка с кодом вида `YD-1234`. Ожидающих заявок может быть не больше 3, новых не больше 5 в час. Админам приходит push.
2. Пользователь переводит деньги на карту и пишет код в комментарии к переводу.
3. Админ находит перевод и подтверждает заявку в админке. Фото начисляются один раз, пользователю приходит push. Если перевода нет, админ заявку отклоняет.

Админ может и сам поправить баланс (`POST /api/admin/users/:id/credits`, ниже 0 не уходит). Каждое начисление пишется в `credit_ledger`.

Реквизиты задаются только переменными окружения сервера, в репозитории их нет:
- `PAYMENT_CARD_NUMBER` — номер карты. Если пусто, покупка выключена и эндпоинты покупки отвечают `503 payments_unavailable`.
- `PAYMENT_CARD_HOLDER` — владелец карты.
- `PAYMENT_TELEGRAM` — Telegram для вопросов по оплате, без `@`.

## 4. Технологии

**Бэкенд (Go 1.22)**
- Фреймворк Gin, база PostgreSQL 16, 44 миграции в `migrations/`, применяются автоматически при старте (`AUTO_MIGRATE`).
- Слои: `domain` → `service` → `repository/postgres` и `handler`. Это чистая архитектура, где домен не зависит от транспорта и хранилища.
- ИИ: Anthropic API через собственный клиент (`internal/provider/anthropic`). Он занимается поиском слов, примерами, историями, фото и проверкой слов. Результаты кешируются в БД (кеш поиска, кеш проверки слов), версии кеша сбрасываются миграциями.
- Авторизация: JWT access-токен на 15 минут плюс refresh-токен на 30 дней в httpOnly-cookie.
- Защита: лимиты запросов в памяти процесса (вход — по IP, ИИ-запросы — по пользователю), проверка бана на каждый запрос, CORS, доверенные прокси только внутри Docker-сети.
- Трассировка OpenTelemetry уходит в Jaeger.
- Служебные команды: `cmd/api` (сервер), `cmd/backfillgap` (заполнение `example_gap_answer` у старых карточек), `cmd/vapidkeys` (генерация VAPID-ключей).

**Фронтенд (`frontend/`)**
- React 18, TypeScript, Vite, Tailwind 4.
- React Query для данных, React Router для страниц, i18next для трёх языков интерфейса (en, ru, uz).
- Тесты на Vitest и Testing Library.

**Инфраструктура (`docker-compose.yml`)**
- Контейнеры: `postgres`, `backend`, `caddy` (раздаёт собранный фронтенд и проксирует `/api/*`), `jaeger`, а также `beszel` и `beszel-agent` для мониторинга сервера.
- Caddy сам получает HTTPS-сертификат (Let's Encrypt), перенаправляет `www` и обращения по IP на `yodla.fun`.
- Хешированные ассеты кешируются навсегда, остальное (index.html, sw.js, манифест) перепроверяется на каждый запрос.
- Мониторинг Beszel закрыт от интернета, вход только через SSH-туннель (см. README). Алерты уходят в Telegram.

## 5. Запуск и разработка

```sh
make up      # docker compose up -d: вся инфраструктура
make run     # бэкенд локально (нужен .env)
make test    # go test ./...
cd frontend && npm run dev     # фронтенд, dev-сервер
cd frontend && npm test        # тесты фронтенда
```

Ключевые переменные окружения: `JWT_SECRET` (не короче 32 символов), `DATABASE_URL`, `ANTHROPIC_API_KEY`, `CORS_ORIGINS`, `COOKIE_SECURE`, `VAPID_*`, `PAYMENT_*`, `OTEL_EXPORTER_OTLP_ENDPOINT`.

## 6. Что в проекте принципиально

- Слово всегда связано с контекстом, в котором оно встретилось.
- ИИ не доверяют вслепую: ответы валидируются на сервере, а слабые входные данные (плохое фото) отсекаются на устройстве, до запроса и до траты квоты.
- Дорогие ИИ-функции ограничены квотами и лимитами частоты, а админ может управлять ими для каждого пользователя отдельно.
